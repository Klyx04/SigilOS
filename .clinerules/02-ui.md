# Règles UI

- **Deslop** : rayons ≤ 12 px (sauf exception mesurée), pas de `glass-premium`, pas de `font-black`/`italic` décoratif, une seule teinte d'accent par écran.
- **Une seule DA, celle de la landing** : tokens uniquement (aucune couleur en dur `emerald`/`amber`/`zinc`/`indigo`), pas de boîte dans la boîte, aucun contrôle natif non thémé ; surfaces flottantes sous les modales (`z-40` < `z-50`). Détail : `docs/RULES.md` § UI.
- **Responsive** : tester 390 / 768 / 1024 / 1440 ; pas de largeur fixe qui déborde ; `w-[min(...,calc(100vw-2rem))]`.
- **Icônes** : assets Dofus réels (`GameIcon`, `public/assets/dofus/...`), pas de glyphe générique quand un asset existe.
- **Serveur/client** : garder les composants client petits ; ne jamais importer de code serveur dans un composant client.
- **Accessibilité** : bouton = `<button>` avec `aria-label` si icône seule ; focus visible ; pas de `div onClick` sans clavier.
- **Images** : passer par les composants maison (`MarketItemIcon`, etc.) et prévoir un repli d'erreur.
- **Textes** : français, aucune mention de fournisseur interne côté utilisateur (DofusDB/Dofensive).
- **DA « Gouache Wakfu »** : tout habillage du module Rush (overlay, guide public, guide membre) suit `.cline/skills/sigilos-da-wakfu/` — tokens `--da-*` de `src/app/da-wakfu.css` uniquement. Préfixe obligatoire : le `--muted` global est une **surface**, celui de la DA est un **texte**.
- **Habillage seul** : une refonte visuelle ne déplace aucun bouton, ne réordonne aucun bloc, ne change aucun libellé ; logique métier et server actions intactes.
- **Rayons — exceptions mesurées** : fenêtre 14 px et coin de carte 4/14 px (signatures de la DA), seules dérogations à « ≤ 12 px », verrouillées par `tests/unit/da-wakfu.test.ts`.
- **Coût de rendu** : jamais de `filter` sur une liste de cartes ; overlay en `data-quality="low"` (grain et filtres coupés), guide en `high`.
- Détail : `docs/CONTEXT.md` + `docs/RULES.md` § Code Organization.
