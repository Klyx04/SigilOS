## 📝 Session 30/10/2026 (suite 2) — **DJ : la dernière place ne se prend plus deux fois (transactions sérialisables)** — branche `fix/dj-serialisable`

> **Demande user (verbatim)** : « deux clics simultanés sur la dernière place peuvent encore passer tous les deux — fais ce lot ».
> **Mesure (sonde DB locale, 30/10/2026)** : `prisma.$transaction(..., { isolationLevel: "Serializable" })` fonctionne avec `@prisma/adapter-pg` ; deux transactions concurrentes qui lisent puis écrivent ⇒ l'une **commit**, l'autre est **annulée** (SQLSTATE `40001`, « could not serialize access »). Codes remontés par Prisma : **P2034** (opérations de modèle) et **P2010** dont le message porte ``Code: `40001` `` (requêtes brutes) — P2034 n'est **pas** utilisé dans ce second cas.
> **Fait** : ① rejeu borné `retryOnWriteConflict` (`src/lib/retry-write-conflict.ts`, **3** tentatives, conflits seuls, attente injectable, dernière erreur relancée) ; ② `withDjSerializableTransaction` (`src/server/dj-join-transaction.ts`) — `Serializable` + `maxWait` 5 s / `timeout` 10 s + journal du rejeu ; ③ les **4** chemins qui écrivent la capacité y passent : `joinDjPost`, `internalJoinDjPost`, `acceptDjParticipant`, `leaveDjPost` (départ **et** promotion dans la même transaction) ; ④ l'effet de bord du départ (notification de promotion) est **déplacé après le commit** — une transaction rejouée ne notifie jamais deux fois.
> **Preuves** : sonde réelle sur un post à **2** places (créateur + 1) — deux joins simultanés ⇒ un `ACCEPTED` + un `PENDING`, **jamais 2/1** (`SONDE_OK`, post de sonde supprimé) ; verrou neuf `dj-serialisation-capacite` **13/13** (prédicat P2034/40001/40P01/P2010, bornes du rejeu, câblage des 4 chemins, aucun `$transaction` parallèle) · suite **538 fichiers / 5 644 tests ✓** · `tsc` **0** · ESLint **0 erreur**. **Aucune migration.**
> **Reste / ops** : ① `updateDjPost` (promotion déclenchée par une **augmentation de taille**) reste un lire-puis-écrire hors transaction — acteur unique (le créateur), fenêtre étroite, à sérialiser si mesuré ; ② `internalLeaveDjPost` (Discord) ne promeut personne : rien à sérialiser ; ③ **CVE-2026-111497** (Node2Shell, décodeur Brotli, RCE HIGH) : `.nvmrc` = **24.22.1** = version corrigée du 21/10, conteneurs locaux mesurés en **v24.22.1** — bêta/prod à **reconstruire** (`./scripts/deploy-cd.sh beta` puis `docker exec … node -v`) ; 24.22.2 (28/10) est un patch **non-sécurité**.
