Oui, je vois le vrai problème : ce n’est pas de mapper les items, c’est le fait que ton serveur essaie d’ouvrir les URLs Dofusbook en boucle, et ce type d’automatisation finit justement en blocage Cloudflare ou en 403 d’après des retours de devs Dofus.
​
Si “tout le monde utilise Dofusbook”, la bonne conclusion n’est pas forcément “tout le monde le scrape côté VPS”, mais plutôt “tout le monde s’appuie sur Dofusbook comme source de build, puis importe les données autrement”.
​

Ce qui coince
Dofusbook est un site centré sur ses outils de build et de copie d’équipements, avec des liens de partage et des fonctions de duplication de stuff déjà présentes dans l’usage produit.

En revanche, des retours publics indiquent qu’un script qui va trop vite se fait bloquer par Cloudflare, donc ton import “URL Dofusbook 
→
→ parse serveur” restera fragile même si tu bricoles un peu autour.
​

Architecture viable
Le plus solide, c’est de ne plus résoudre le lien Dofusbook sur ton backend.
Fais l’import côté navigateur utilisateur, puis envoie à ton API un JSON propre contenant seulement les IDs, noms et slots des items ; pour enrichir ensuite les métadonnées, tu peux t’appuyer sur Dofapi, qui expose justement l’encyclopédie Dofus via des requêtes REST par catégories d’objets.

Deux options propres
Option 1 : extension Chrome / userscript Tampermonkey sur Dofusbook ; l’utilisateur ouvre son stuff, clique “Exporter vers le dashboard”, le script lit la page déjà chargée et poste le JSON vers ton API.

Option 2 : bookmarklet ou petit snippet exécuté par l’utilisateur dans la page Dofusbook ; même idée, mais sans maintenir une vraie extension.

Ces approches collent mieux au fonctionnement réel de Dofusbook, qui est pensé pour manipuler et copier des stuffs depuis l’interface utilisateur.

Elles évitent aussi que ce soit ton IP VPS qui prenne tous les blocages anti-bot.
​

Flux recommandé
L’utilisateur colle un lien Dofusbook dans ton dashboard.

Ton front ouvre Dofusbook dans un onglet et demande une action “Importer ce stuff”.

Le script client extrait la liste des items visibles et envoie un payload minimal à ton backend.

Ton backend résout chaque item via ta base locale ou Dofapi, puis affiche la galerie.

Concrètement, ton backend ne devrait plus faire “GET https://dofusbook…”, mais seulement recevoir quelque chose comme { source: "dofusbook", items: [{ slot, name, itemId? }] }.
C’est ce découpage qui te sort du piège “403/IP ban” tout en gardant Dofusbook comme point d’entrée utilisateur.
​

Ce que je ferais à ta place
Je garderais Dofusbook comme entrée UX, mais je déplacerais tout l’extract dans le navigateur et tout le référentiel item chez toi.
Le combo “import client depuis Dofusbook + enrichissement via Dofapi + miniatures servies par ton dashboard” est beaucoup plus stable que “scraping serveur de liens Dofusbook”.

Je peux te proposer directement le plan d’implémentation en TypeScript pour l’option extension/userscript, avec le format JSON exact et le endpoint API à prévoir.
